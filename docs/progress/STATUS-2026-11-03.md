# Status — 2026-11-03

## 2026-11-03 — delivery drain and autonomy fixes (current state)

**Automatic decompilation is running.** `nova3-dsh-worker.service` claims tasks,
runs one bounded DSH session per task on a routed model (currently
openai-codex/gpt-6.1-sol or openrouter deepseek per task), verifies in the task's
own checkout, commits, pushes and opens a PR. The autopilot timer approves
planner proposals, marks mergeable work ready and merges reviewed+green PRs two
at a time.

**Drained today: 50 PRs merged.** The 41 draft PRs that had accumulated were
promoted properly (merge current main, run the suite in that checkout, push,
mark ready) and merged; two were closed as genuinely superseded (#190 divergent
tool rewrite, #191 conflict file was the append-only log — resolved by keeping
both entries).

Root causes fixed on main (each with a test where testable):
1. `test_worker_timeout` gave a fresh Python child 2 s — load-dependent flake
   that failed verification and made EVERY PR a draft. Now 20 s.
2. `autopilot.tick()`'s approve path crashed with `'bool' object is not callable`
   (the `merge=` keyword shadowed helpers; `approve()` renamed to
   `approve_proposal()`). This is why the timer never approved anything.
3. The autopilot merge scan reviewed drafts it would refuse, so the 180 s unit
   timeout killed it before any merge landed. It now scans ready PRs
   oldest-first with a deadline; the unit timeout is 900 s.
4. A checkpoint at `committed`/`pushed` reloaded `verified=False` and published
   drafts forever; it now re-runs the independent checks in that checkout.
5. `run_provider` now drains the output relay (bounded) before the activity
   publish.
6. Task verification retries a command exactly once (`run_verification_command`):
   this host loses its link for a few seconds at a time, and one false FAIL used
   to become a permanent draft.

**Still open / not claimed:** a single PR may remain right after a worker round
until the next autopilot tick merges it. Draft PRs still appear whenever a
task's own verification genuinely fails — that is correct behaviour, and the
task body carries `Last local verification` evidence.

**Known unproven:** one test (`test_structured_stream_and_independently_observed_file_count`)
failed inside worker processes while passing 8/8 standalone and inside
`worker.verify()` standalone; the cause was not established. The relay drain is
the plausible fix; if it recurs, capture `round-1.activity.json` from the task's
private dir before retrying.
