# NOVA3 unattended GitHub reconstruction backlog

The `NOVA3 automatic task replenishment` GitHub Actions workflow runs twice an hour, on relevant `main` changes, and whenever `main` receives a push. It (1) reconciles *actually merged* NOVA3 PRs with issues, (2) reads a checked-in function ledger or explicitly publishable task manifest, (3) creates up to 8 additional queued issues per run, and (4) refreshes the live status issue. It caps pending/claimed/review issues at 24. `GITHUB_TOKEN` needs **Issues: write** and **Contents: read**. It does not execute untrusted PR code and doesn't distribute APKs, OBBs, `.so` files, original assets or dumps.

## How function work enters the queue

Preferred file: `coordination/tasks.json`. This may be generated by the project's existing deterministic queue generator (from issue #4) after verified source identification. Minimal example:

```json
{"tasks":[{"id":"native-elf-1234","publish":true,"status":"pending","title":"Reconstruct verified cluster 1234","priority":75,"allowed_paths":["reconstruction/recovered/native/cluster_1234.cpp","reconstruction/tests/recovered/native/cluster_1234_test.cpp"],"description":"Use validated reference identifiers and record independent matching evidence."}]}
```

Fallback: `coordination/function_ledger.json`, populated with **metadata only** using `nova3_team.indexer --format coordination` as described below. Each record carries a locally calculated reference SHA-256, integer ARM virtual address and byte size, explicit Thumb mode, boundary confidence and tool provenance. This is an *incomplete* function census; it does not attest to assembly matches. Current grouping is a bounded four-function fallback; a dependency-aware queue-generator manifest should eventually replace it. The private `nova3.function-ledger/1` inventory and the queue generator's dependency ledger are different formats; do not copy either directly into this fallback file.

### Export verified local metadata

Supply a lawfully held ELF and its local `tools/ghidra/export_batch.py` JSON records. This operation reads those files and prints metadata; it does not run the original executable, invoke Ghidra, change references or contact any service. Keep the default private inventory output local. To prepare feeder metadata:

```bash
python3 -m nova3_team.indexer "$REFERENCE_ELF" \
  --ghidra-directory "$GHIDRA_EXPORT_DIR" \
  --format coordination > /tmp/nova3-function-ledger.json
python3 -m unittest nova3_team.tests.test_indexer nova3_team.tests.test_task_queue \
  nova3_team.tests.test_autofeed nova3_team.tests.test_local_index -q
```

The library basename must be `lib*.so`; `--library libName.so` can supply it explicitly. `--ghidra-export FILE` selects individual records and may be repeated. Directory input reads only immediate `*.json` members. Input limits are 100,000 records, 4 MiB per record and 64 MiB combined. Review the temporary result and reconcile any existing function statuses before replacing `coordination/function_ledger.json`. A failed command can leave an empty redirected temporary file; do not install it. The exporter exits 2 without JSON when no acceptable boundaries exist. Missing references or an empty result leave the prerequisite **BLOCKED**, not completed.

For each supplemental record, the exporter checks the locally calculated ELF hash, ARM architecture/endianness, canonical address, raw Thumb bit, symbol name and size, and the reported Ghidra address/rebase. Only defined `STT_FUNC` symbols inside executable file-backed ELF sections qualify. Publishing also requires a Ghidra mapping-check report and numeric Ghidra version. It omits unknown sizes, conflicting aliases/modes, intersecting extents, unaligned extents, sizes above 1 MiB and missing Ghidra evidence. Malformed or mismatched records fail the entire export; no partial ledger is emitted. Exclusion counts remain visible.

`boundary_confidence: elf_symbol_with_ghidra_mapping_report` means exactly that: bounds come from an ELF symbol and corresponding Ghidra metadata reports a byte-mapping check. The importer does not independently recheck that report, disassemble instructions or authenticate who produced the export. Ghidra's function body may have been assigned from the same symbol size. The result therefore stays `tool_identified`, `INVENTORIED` and **NOT MATCHED**. No names, instruction bytes, pseudocode, calls, local paths or arbitrary export strings enter the public ledger.

The initial checked-in ledger contains 62 such Premium boundaries, cross-checked against local ELF bytes with SHA-256 `84075223e7e7f833ebba98a46756ce4619fb909663cd0b961e440cc048abbaaf`. GNU readelf 2.47 independently agreed on all 62 address/size/Thumb tuples. The local scan inventoried 39,092 distinct address/mode pairs with function symbols; it excluded 38,999 without Ghidra evidence, 13 with unknown sizes, 2 with conflicting sizes and 16 with overlapping extents. The existing feeder accepts the ledger and previews 16 bounded clusters offline. These are metadata checks: **zero source implementations or behavioural/machine-code matches are established by this ledger**. No game-completion percentage follows from these counts. The local references and Ghidra exports are not included.

If all currently identified function tasks are integrated, the feeder creates **one** evidence-expansion issue per ledger revision, so the project cannot mistake an empty queue for complete source recovery. The issue can only succeed if someone can provide additional real function evidence locally. If neither metadata source exists, the feeder creates **one** prerequisite issue (not infinite fabricated work). If that issue is closed without the necessary metadata, it reopens **blocked** instead of endlessly rerunning the same task. When real reference metadata becomes available, new function tasks can be generated. Contributors doing byte matching need their own lawfully available local reference files; GitHub cannot automatically supply private APKs that are not checked in.

### Inspect additional functions without changing a saved Ghidra project

`nova3_team.local_index.collect_program` is an optional PyGhidra API for a locally
opened **read-only** `Program`. It verifies the program's executable SHA-256,
architecture and image base against separately read ELF bytes. Its default mode
accepts existing contiguous bodies equal to the ELF symbol extent. With
`disassemble=True`, it instead attempts bounded disassembly of small symbol
extents in a transaction that is rolled back even on failure. It attempts at
most `limit * 4` candidates, each at most 256 bytes; `limit` is 1–256 and defaults
to 32. It disables follow-up code analysis and requires complete instruction
coverage, agreement on ARM/Thumb mode and full-extent byte comparison. It never
calls the decompiler, executes game code or saves the program.

Example, using the locally installed PyGhidra environment and explicit local
paths (the output is allowlisted metadata only):

```python
import json
import tempfile
from pathlib import Path
from pyghidra.launcher import HeadlessPyGhidraLauncher
from nova3_team.local_index import collect_program

# Set these to local installations/references; no downloads are performed.
reference = Path(REFERENCE_ELF)
baseline = json.loads(Path("coordination/function_ledger.json").read_text())
with tempfile.TemporaryDirectory(prefix="nova-inventory-") as scratch:
    launcher = HeadlessPyGhidraLauncher(install_dir=Path(GHIDRA_INSTALL_DIR))
    launcher.java_home = Path(JDK_HOME)
    launcher.vm_args.extend([
        "-Duser.home=" + scratch,
        "-Dapplication.settingsdir=" + scratch + "/settings",
        "-Dapplication.cachedir=" + scratch + "/cache",
        "-Dapplication.tempdir=" + scratch + "/temp",
    ])
    launcher.start()
    from ghidra.framework import Application
    from ghidra.framework.data import DefaultProjectData
    from ghidra.framework.model import ProjectLocator
    from ghidra.util.task import TaskMonitor
    from java.lang import Object

    project = DefaultProjectData(
        ProjectLocator(GHIDRA_PROJECT_DIR, GHIDRA_PROJECT_NAME), False, False)
    consumer, program = Object(), None
    try:
        program = project.getFile("/" + reference.name).getReadOnlyDomainObject(
            consumer, -1, TaskMonitor.DUMMY)
        delta = collect_program(
            reference.read_bytes(), program, library=reference.name,
            ghidra_version=str(Application.getApplicationVersion()),
            excluded_addresses=[f["address"] for f in baseline["functions"]
                                if f["reference_sha256"] == str(program.getExecutableSHA256())],
            limit=32, disassemble=True)
    finally:
        if program is not None:
            program.release(consumer)
        project.close()
print(json.dumps(delta, indent=2))
```

New records include `reference_code_sha256`, calculated over the exact ELF
symbol extent. This is an original-byte inventory hash, **not** a comparison
against compiled replacement source. Bounds still originate from ELF symbols;
complete disassembly does not independently prove the function's semantics or
its true extent. Every record remains `INVENTORIED` / **NOT MATCHED**. An empty
result supplies no new tasks. Recheck tuples with `readelf --wide --symbols` and
check reference/project files remain unchanged before installing metadata.

When adding boundaries before existing addresses, first freeze the existing
fallback task keys in `coordination/tasks.json`, then append tasks generated
from the new rows separately. The four-function fallback groups sorted
addresses, so regenerating it from a combined ledger could reassign existing
work to new keys. Preserve all old function records and task descriptions,
scopes and keys. Keep initial inventory statistics as the original snapshot;
record each additional scan's counts and exclusions in `expansions` rather
than treating separate scans as a complete census. This workflow makes no
dependency-completeness claim.

## Correctness and security

- One serial Actions workflow arbitrates creation; stable task keys ensure reruns do not duplicate old issues, including already closed work.
- Reconciliation closes issues **only** for merged PRs targeting `main` with matching worker-branch and issue reference. A review label alone is not proof of completion.
- `nova:integrated` means merged to the source tree, **not** byte-matched or game complete.
- Existing `nova:blocked` issues are not silently retried. Circuit breakers and a separate claim coordinator still govern workers.
- Missing or unparseable metadata results in a clear visible prerequisite or failed Action rather than invented task numbers.
- Task code is read only from the repository's trusted `main` branch. Keep privileged Actions away from untrusted fork checkouts and secrets.
- If you change repository visibility, first review the Git history and reconstructed game's publication/licensing position. A private cloud is not an authorisation to redistribute someone else's original game binaries.

## Manually preview or trigger (optional)

```
python3 -m nova3_team.indexer --help
gh workflow run nova-autofeed.yml --repo N-O-V-A-3-RE-Contributors/nova3-reconstruction
gh run list --workflow nova-autofeed.yml -L 3
gh issue list --label nova:queued -L 30
```

**No VPS required**. GitHub cron scheduling is not real-time: jobs can be delayed under load. The queue resumes on the next run. No meaningful *full game* percentage or ETA exists until the original function inventory is complete and matching is independently measured.
